# Decompiler backlog status

This file tracks the requested backlog against the current implementation. “Partial” means a bounded subset exists; it does not mean the broad area is complete. Full x86/x64 semantic equivalence and recovery of original source are open-ended goals, so each phase needs an explicit scope and evidence.

## Status by requested area

Overall backlog completion is roughly **90%** by a scope-based estimate. This is not a test pass rate; each of the 12 broad areas below remains partial.

1. **Instruction semantics - Partial.** Common scalar operations are normalized. Partial GPR writes track byte/word/dword slices so reads of al/ah/ax use the right bits and writes preserve unaffected known bits. Data flow tracks CF/PF/AF/ZF/SF/OF for common known arithmetic, including width-limited `neg`, logic, shifts including `shld`/`shrd`, rotates, and bit tests. setcc/cmovcc use known flags, and proven conditional branches prune impossible CFG successors. jcxz/jecxz/jrcxz and loop/loope/loopne model count and flag effects. A bounded x87 subset tracks the abstract ST stack for initialization, constants, loads/stores, exchanges, common arithmetic, integer fild/fist/fistp/fisttp conversions, fcmovcc, and compare/pop effects; known numeric fcomi comparisons set CF/ZF/PF. Joins retain x87 values only when paths agree; unsupported x87 operations widen the stack to unknown. IR reports x87 operations and stack effects. Scalar SSE includes bit-preserving compares/minmax, exact finite add/sub/mul/div folding, exact packed single/double add/sub/mul/div when every lane is exact, bounded integer conversions, exact CVTSS2SD and exact-only CVTSD2SS, packed float comparison predicates 0-7 for legacy and 0-31 for VEX, packed min/max and exact packed square roots, packed integer/float and single/double precision conversions, and `ROUNDSS/ROUNDSD` with all four explicit rounding modes; fractional values using MXCSR-selected rounding widen because MXCSR is not tracked. Integer SIMD supports common packed arithmetic, shifts, logical operations, saturation, averages, comparisons, selected min/max, bounded immediate lane extraction/insertion, packed integer low/high/full multiply, lane-wise unpack and saturating pack operations, MOVMSK sign-bit extraction, byte/immediate-controlled shuffles, pairwise multiply-add/SAD operations, horizontal add/subtract, sign-controlled lane negation/zeroing, signed lane absolute value, immediate-controlled `BLENDPS/PD` and `PBLENDW/D` lane selection, mask-controlled `PBLENDVB/VPBLENDVB`, per-128-bit-lane `PALIGNR/VPALIGNR`, and `PTEST/VPTEST` CF/ZF effects. Concrete XMM/YMM/ZMM folding is provided for these operations, including lane scope, selector semantics, and signed saturation. VEX vector writes propagate zeroed upper aliases, while legacy SSE writes invalidate wider aliases. Memory-form `xadd` and `cmpxchg` now apply known single-thread memory/register transfers and comparison flags when their operands and target memory value are known; uncertain cases widen conservatively, and this does not model inter-thread synchronization or ordering. Unsupported operations remain opaque and conservatively invalidate affected state. x87 exact integer-valued arithmetic now folds when results remain in range; non-integral/inexact results and control-word rounding remain open. x87 status-word and exception behavior, general floating-point arithmetic/conversion beyond the modeled scalar SSE subset, MXCSR and exception behavior, remaining floating-point, crypto, and advanced SIMD coverage, exact address-size/segment behavior, general string memory behavior except bounded known-pointer REP MOVS/STOS/INS, concurrent/atomic ordering semantics beyond the explicit fence markers, and full x86/x64 equivalence also remain open.
2. **Function boundaries — Partial.** PE entry, exports, x64 runtime records, executable unwind-handler entries, direct calls, exported indirect targets, bounded value-flow-resolved calls and tail jumps through registers or unscaled memory, and isolated one-instruction jump thunks can seed candidates. Direct jumps to known function entries are recorded as tail-call/forwarding call references. General tail-call discovery and runtime-function separation remain open.
3. **Indirect calls — Partial.** Import references called directly through the IAT or loaded into a register and called indirectly are named; value-flow reports carry the imported symbol and the pipeline annotates the indirect call. Static aligned pointers in readable non-executable PE sections can resolve memory-indirect calls through a table or a statically addressed global object vptr when value flow proves the object address, vptr slot, and method slot. The pipeline promotes the resolved virtual target and records static-pointer-slot provenance. Bounded Windows x64 value flow records register arguments; x86 value flow tracks up to 16 pushed argument values across CFG edges and reports must-known ESP-relative outgoing stack-slot values separately. Agreed stack facts survive joins, while conflicting facts widen to unknown. Decoded code addresses in these arguments are promoted as callback candidates. This is evidence of a function pointer passed to a call, not proof the callee invokes it. Runtime-dynamic object vtables, arbitrary heap pointers, and whole-program pointer propagation remain open. The example bullets in the request were blank and therefore unspecified.
4. **Jump tables — Partial.** Bounded absolute, image-relative, common x64 signed-relative table entries, indexed memory jumps using a nearby register base loaded by RIP-relative `lea` or an immediate, and x64 register dispatches shaped as `movsxd temp, [table + index*4]; add temp, table; jmp temp` are recovered. The relative-dispatch recognizer requires a bounded sequence, a four-byte scaled index, matching temporary/table registers, and a resolvable table-base LEA; unsupported definitions are rejected. The resolver stops at unsupported or width-changing register definitions and includes constant displacement in the indexed memory operand. Unbounded scanning stops at the first invalid entry and records the contiguous valid-entry count observed; matched guard-bounded scans can preserve later entries across unresolved slots. Nearby `cmp index, immediate` plus unsigned `ja`/`jae` guards infer index and case count. Signed `jg`/`jge` bounds are accepted when a matching `test index,index; js default` or `cmp index,0; jl default` lower guard proves the index is nonnegative and both guards share the default destination. Matched scanning is capped at the recovered count. The bound is reported separately from entries observed. A directly preceding matching SUB, ADD, or LEA can also recover the case-value bias; when the bound and slot positions are known, pseudocode uses that bias to render an indexed switch with explicit destinations and unresolved slots. For a matched out-of-range guard, the branch target is recorded as the default target and table slots that repeat that target are reported by index. Unproven sparse layouts, alternate bases, other default/fallthrough layouts, broader bounds patterns, and compiler-specific formats remain open.
5. **Memory alias analysis — Partial.** Exact repeated expressions and stack slots are tracked; equivalent numeric offset spellings canonicalize to one memory key. Stack facts include access width, overlapping writes invalidate prior facts, mismatched-width reads become unknown, and joins discard conflicting-width facts. Simple non-stack addresses canonicalize through equal concrete pointer values or stable symbolic arguments plus/minus constant offsets. `lea` propagates canonical concrete and symbolic base-plus-constant addresses into later dereferences; up to four scaled indices also propagate when their values are stable or concrete. Non-stack stores now preserve proven-disjoint ranges under the same concrete or symbolic base, invalidate overlapping ranges, and conservatively evict facts when bases may alias or ranges cannot be parsed; reads still require matching widths. Unknown calls invalidate non-stack facts. General/heap pointer aliasing, cross-base stack normalization, unknown scaled indices, more than four index terms, structure fields, volatility, concurrency, and memory SSA remain open; up to four known scaled index terms are canonicalized independent of order when one pointer base and stable index values are proven. The example bullets in the request were blank and therefore unspecified.
6. **ABI and arguments — Partial.** Windows x64 GPR arguments, scalar XMM0–XMM3/vector register candidates, and observed stack parameters beyond the 32-byte shadow space receive heuristic treatment; vector candidates retain their ABI slot positions, scalar single/double uses get basic type hints, and known direct calls forward tracked vector register values. Register parameters used as memory bases or indirect-call destinations before a local write receive a conservative `uintptr_t` hint in x86 and x64 signatures; direct calls cast those arguments accordingly. Entry-block RSP and established RBP offsets are normalized through simple prologues and share names between signatures and pseudocode. Direct calls can pair known callee stack parameters with outgoing RSP values after constant stack reservation, including same-block pushes and immediate qword stores propagated across CFG edges. Register constants, unchanged argument values, copies, and simple immediate arithmetic can feed those stores across blocks. Facts survive joins only when every path agrees; unknown writes/calls invalidate register facts. Ambiguous RSP paths remain unknown. x86 conventional EBP-frame and locally trackable ESP-relative stack parameters, `ret N` cleanup, cdecl/stdcall/fastcall candidates, possible thiscall, and direct-call arguments from pushes or direct ESP-relative stores are now inferred. Outgoing x86 stack-slot values and stack depth propagate across CFG edges and joins only when unambiguous; known direct-call signatures map those slots to recovered stack parameters. Mixed push/store layouts remain conservative because argument order is ambiguous. A shared bounded import-signature catalog supplies parameter arity for common C runtime and Win32 APIs, including allocation, module/function lookup, process/file handles, and selected event APIs. Data flow separately preserves up to 16 pushed values across the function CFG for call-site callback discovery, in reverse-push calling order, and widens conflicting joins. Known direct-call signatures produce explicit placeholders for missing visible x86 stack arguments. At x86 call-site CFG joins, equal-depth push histories retain agreeing positions; differing depths below the tracking cap retain only agreeing chronological positions and widen missing/conflicting pushes to unknown. Placeholder numbering follows source parameter position, so a known older push is not mislabeled when a newer argument is missing; simple caller cleanup via `add esp, N`, `lea esp, [esp+N]`, or `pop` removes tracked pending pushes. Resolved x86 indirect calls with known callee arity now include tracked pushed arguments in the call expression and explicit placeholders for missing visible arguments. Known direct-call and proven resolved tail-jump targets propagate return-type hints to callers; fully reliable convention discrimination, vector/FPU type discrimination, hidden structure returns, variadics, and precise types remain open.
7. **Exceptions and unwind flow — Partial.** The loader decodes bounded x64 unwind opcodes, handler RVAs, and chained runtime-function references; executable handler entries can seed function candidates. The program report emits `exceptional_edges` linking handler-bearing ranges to handler candidates, clearly marked as metadata candidates rather than proven branches. It also emits `chained_unwind_relationships` linking primary records to valid chained ranges and indicates whether the target entry was recovered. SEH/C++ scope tables, language-specific handler semantics, actual exceptional CFG edges, and cleanup/catch flow remain open.
8. **Control-flow structuring — Partial.** Safe diamonds, simple loops, direct comparison-chain switches, and some fallthrough are structured. Multi-block loop bodies with one header and one exit now convert explicit edges to that header/exit into `continue`/`break`, including an enclosing loop that contains a cyclic inner region. The inner cycle keeps its explicit labels and gotos, preserving its CFG edges; complete nested-loop structuring, irreducible regions, multiple exits, complete branch structuring, and an internal structured AST remain open.
9. **Source-level types — Partial.** Conservative scalar/stack hints and conflict widening exist. A shared bounded import catalog distinguishes pointer-sized returns, `size_t`, `bool`, signed 32-bit results, void, and selected pointer parameter types for common C runtime and Win32 APIs. Register parameters used as memory bases or indirect-call destinations before a local write receive conservative pointer-sized types, which flow into direct-call casts. Pointer/size return types from imports propagate through direct wrapper returns and into caller value-flow hints. Known import pointer parameters appear in value-flow metadata and produce casts in call expressions; unknown positions remain untyped. Known allocation APIs and buffer-returning APIs retain `uintptr_t` hints; common deallocation APIs produce `void`. Hints propagate through register and stack writes and through tracked non-stack memory facts when access widths match; memory-type facts merge only when paths agree and are invalidated with their memory values. The catalog and pointer-use heuristic are incomplete; aggregate/class/enum recovery, fields, function-pointer types, and general memory/call propagation remain open. The requested example list contained blanks.
10. **Pseudocode — Partial.** Register/stack-level C-like output and local expression simplification exist. Guard-proven jump tables with recovered slot positions render as a switch using the inferred case bias; valid slots target recovered labels and unresolved slots remain opaque. If the scanned slot vector does not cover the full proven bound, dispatch stays indirect rather than treating missing cases as default. General variable recovery, reliable casts/call signatures, complete switch-body structuring, and compilable source reconstruction remain open.
11. **Real-PE validation — Partial.** Hand-built, valid PE32 and PE32+ fixtures containing actual x86 and x86-64 machine code pass through the real PE loader, Capstone decoder, CFG, and full pipeline in reproducible integration tests. An x64 fixture also contains a real IAT-backed `GetLastError` call and `.pdata`/`.xdata` runtime-function unwind record; tests verify symbols, unwind metadata, and emitted call pseudocode. These fixtures are still minimal and hand-built, and do not cover relocations, jump tables, realistic compiler output, exception handlers, or optimization diversity. A reproducible x86/x64 MSVC/MinGW and C/C++ corpus remains open.
12. **Performance and scale — Partial.** Instruction/function/output budgets exist. The pipeline now supports cooperative cancellation checks and stage/per-function progress callbacks across function indexing, indirect-call discovery, CFG rebuild, data flow, normalized IR/SSA, and pseudocode. CLI progress is opt-in with `--progress`; Ctrl+C requests a stop at the next checkpoint, writes valid partial reports marked `analysis_complete: false` and `cancelled: true`, then exits with status 130. A mocked-PE regression verifies partial function reports and cancellation metadata. Parsing/disassembly and other monolithic stages do not yet have internal checkpoints; incremental analysis, persistent databases, caching, and parallel function analysis remain open.

## Latest completed phase

Windows x64 ABI recovery now detects XMM0–XMM3 read-before-write candidates, preserves their positional slots alongside GPR candidates, assigns scalar `float`/`double` hints from observed scalar SSE use, and forwards known XMM values through calls with recovered signatures. Vector types and ambiguous GPR/XMM use remain heuristic. Regressions cover float parameter declarations, call-site propagation, and the existing integer/stack paths. Full suite: 239 tests.

Packed `CVTPS2PD` and `CVTPD2PS` plus VEX forms now fold exact single/double lane conversions, including the differing source and destination vector widths. Inexact double-to-single lanes and NaNs widen to unknown; VEX destination upper bits follow vector zeroing rules. Typed IR records lane widths, precision direction, and exactness requirements. Focused tests and the full suite pass: 238 tests.

Packed `CVTDQ2PS`, `CVTPS2DQ`, and `CVTTPS2DQ` plus VEX forms now fold exact signed-dword-to-float conversions, MXCSR-independent integral float-to-int conversions, and truncation-toward-zero conversions. Inexact integer-to-float results, fractional MXCSR-rounded inputs, subnormals, NaNs/infinities, and out-of-range lanes widen to unknown. Typed IR records element types and rounding rules. Focused tests and the full suite pass: 236 tests.

Packed `MINPS/MINPD/MAXPS/MAXPD` and VEX forms now select source lane bit patterns directly, including the architectural second-source selection for ties and NaNs. `SQRTPS/SQRTPD` and VEX forms fold zero and exact nonnegative square roots lane by lane; negative, subnormal, exceptional, and non-exact results widen conservatively. Typed IR records lane precision, tie behavior, and the exact-fold boundary. Focused tests and the full suite pass: 234 tests.

Packed `CMPPS/CMPPD` and VEX forms now fold legacy predicates 0–7 and all 32 AVX predicates lane by lane, including ordered/unordered NaN behavior and all-ones/all-zero comparison masks. Signaling exception status is not modeled. Typed IR records the predicate operand, lane precision, and result mask form. A 32-case semantic regression and the full suite pass: 232 tests.

Packed `ADDPS/ADDPD`, `SUBPS/SUBPD`, `MULPS/MULPD`, and `DIVPS/DIVPD` plus VEX forms now fold only when every lane has an exact finite normal result. Inexact, exceptional, subnormal, or rounding-sensitive zero lanes conservatively widen the vector result. Typed IR records precision, lane width, and that exception flags are not modeled. Focused regressions and the full suite pass: 230 tests.

Scalar `CVTSS2SD` and `CVTSD2SS` plus VEX forms now fold exactly representable finite values and signed infinities/zeros while preserving scalar upper lanes according to legacy/VEX rules. NaNs and inexact double-to-single narrowing remain unknown; typed IR records precision direction and exactness requirements. Focused tests and the full suite pass: 228 tests.

Scalar `ROUNDSS/ROUNDSD` and VEX forms now fold nearest-even, down, up, and truncate modes when the instruction explicitly selects its rounding mode. Signed zero and scalar upper-lane preservation follow the instruction form. When the immediate selects MXCSR, fractional inputs widen to unknown because MXCSR state is not modeled; NaN/infinity and already-integral inputs remain bit-preserving. Typed IR documents the control source. Focused tests and the full suite pass: 226 tests.

`PALIGNR/VPALIGNR` now fold immediate byte alignment from the concatenated source pair independently within each 128-bit lane, with zero results for shifts of at least 32 bytes. `PTEST/VPTEST` now set known CF and ZF when vectors are concrete and widen both flags for unknown inputs. Typed IR records lane scope and flag definitions. Focused regressions and the full suite pass: 224 tests.

Variable-mask integer SIMD blends (`PBLENDVB` and `VPBLENDVB`) now select each byte from the corresponding source using the mask byte's sign bit. Legacy `PBLENDVB` reads the implicit `XMM0` mask; VEX `VPBLENDVB` uses its explicit mask operand and supports concrete 128/256-bit values. Typed IR exposes the mask source and control semantics. Focused tests and the full suite pass: 222 tests.

Immediate integer SIMD blends (`BLENDPS/PD`, `PBLENDW/D` and VEX forms) now fold concrete vectors according to the encoded selector bits. VEX operands retain distinct first-source/second-source ordering; word selectors repeat independently for each 128-bit lane in wider vectors. Typed IR records blend lane width and selector behavior. Focused tests and the full suite pass: 220 tests.

Packed integer SIMD now folds horizontal add/subtract (`PHADDW/D`, `PHSUBW/D`, and signed-saturating `PHADDSW`/`PHSUBSW`), sign-controlled lane operations (`PSIGNB/W/D`), and signed absolute-value lanes (`PABSB/W/D`). Wider vectors process each 128-bit lane independently. Typed IR records lane widths, signed saturation, control semantics, and minimum signed-lane wraparound. Focused regressions and the full suite passed: 218 tests.

Pairwise integer SIMD now models PMADDWD with wrapping dword sums (including the signed overflow corner case), PMADDUBSW with signed saturation, and PSADBW as unsigned byte-difference sums placed in 64-bit lanes. Data flow folds concrete vectors; typed IR describes input/output lane widths and pairwise behavior. Focused tests and the full 216-test suite pass.

Integer bit semantics now include POPCNT, LZCNT, TZCNT, BSF, and BSR, with operand-width handling, distinct zero-input results, and known flag updates where defined. BMI1 ANDN, BLSI, BLSMSK, and BLSR also fold concrete operands and update their defined CF/ZF/SF/OF effects while leaving undefined flags unknown. Typed IR exposes each operation and its zero/flag behavior. Focused regressions and all 214 tests pass.

Packed shuffle support now includes PSHUFB/VPSHUFB, PSHUFD/VPSHUFD, PSHUFLW/HW VEX and legacy forms, and SHUFPS/SHUFPD VEX and legacy forms. Byte controls honor high-bit zeroing; immediate selectors fold per 128-bit lane, including 256/512-bit repeated-lane behavior. Typed IR records lane width and control form. Focused value-flow tests and the full suite pass; broader cross-lane permutations, blends, floating/crypto shuffles, and compiler-specific idioms remain open.

MOVMSKPS, MOVMSKPD, and PMOVMSKB now fold concrete vector sign bits into scalar masks and have explicit IR result-width metadata. Saturating PACKSSWB, PACKSSDW, PACKUSWB, and PACKUSDW now clamp signed input lanes and pack per 128-bit lane, including wider VEX vectors. Focused regressions and the full suite pass.

Packed PUNPCKL/H byte, word, dword, and qword forms now interleave the selected source halves, independently within each 128-bit lane for wider VEX vectors. The value folder and typed IR record lane width and source half. Focused tests cover low/high ordering and 256-bit lane independence; general shuffles, blends, and cross-lane permutations remain open.

The packed integer SIMD folder and IR now model PMULLW, PMULHW, PMULHUW, PMULLD, PMULDQ, and PMULUDQ, including signed high-half extraction and the even-dword/full-qword lane mapping. Focused regressions cover arithmetic lane results and IR metadata. Floating-point vector multiply and additional AVX-512-specific forms remain open.

The bounded x87 interpreter and IR now model FABS and FCHS as ST0-only operations. Exact numeric stack values fold through absolute value/sign change; symbolic values retain an explicit unary expression, and unknown/empty stack states remain conservative. Focused x87 and IR tests pass.

Scalar SSE conversion handling now covers CVTSI2SS/CVTSI2SD when the signed integer converts exactly, CVTTSS2SI/CVTTSD2SI with truncation toward zero, and rounding-mode-sensitive CVT*2SI only when the source is already integral. Exceptional, out-of-range, subnormal, and inexact integer-to-float results widen to unknown. Typed IR records the conversions and their rounding constraints.

Scalar SSE MINSS/MAXSS and double precision forms now select exact source bits, including the architectural second-source selection for unordered or equal operands. This preserves NaN payloads and signed zero at the data-flow level; floating exception status is not modeled. Typed IR records the selection rule.

Scalar SSE ADDSS/SUBSS/MULSS/DIVSS and double-precision forms now have typed IR and bounded constant folding. Folding requires finite normal inputs and an exact normal finite result, so it is independent of MXCSR rounding/flush modes; inexact, subnormal, exceptional, zero-result, and unknown cases widen to unknown. Legacy upper lanes are preserved, and VEX forms take upper scalar lanes from their first source and apply vector upper-alias zeroing.

Scalar SSE comparisons (COMISS/UCOMISS and double precision forms) now set CF/ZF/PF for known operands, including the unordered-NaN result; SF/OF/AF are cleared as required. Conditional branches can consume these flags. Unknown operand bits widen the affected flags. Arithmetic beyond the exact normal finite subset, MXCSR controls, signaling-NaN exceptions, and exact NaN payload/exception behavior remain unsupported.

Fence handling now recognizes LFENCE, SFENCE, MFENCE, and SERIALIZE explicitly in IR and data-flow reports. Fences preserve ordinary single-thread register and memory facts while exposing a load/execution, store, full, or serializing order marker; PAUSE is represented as a no-effect spin-wait hint. This does not model inter-thread happens-before, cache coherence, or the complete ordering guarantees of a concurrent program.

String value flow now handles bounded known absolute-pointer MOVS, STOS, and INS ranges (up to 256 elements), propagating copied/fill values or invalidating only the written range while preserving proven-disjoint facts. For CMPS/SCAS with known memory/accumulator values, count, and direction, REP/REPE/REPNE simulation stops at the correct comparison result, updates pointers and remaining count, and computes subtraction flags. Unknown or larger cases widen conservatively. Segment overrides, I/O strings, general dynamic pointers, and general compare/scan flag behavior remain open.

The SIMD value-flow and normalized IR now support concrete extraction and insertion of immediate-selected byte, word, dword, and qword lanes (`PEXTR*`, `PINSR*`, and VEX forms), plus extraction of packed single-precision bit patterns via `EXTRACTPS`. Lane indices use the architectural low bits of the immediate. Known vectors/scalars fold to constants; unknown operands remain unknown, and VEX writes apply the existing upper-alias invalidation/zeroing rules. Focused data-flow and IR regressions cover legacy and VEX forms and immediate index truncation. This does not add vector shuffles, runtime lane indices, floating-point insertion, or floating-point arithmetic.

The function-discovery pass now recognizes isolated one-instruction jumps to known functions when the block is outside all bounded function-root traversals; it disables this heuristic if a root traversal hits its block cap. The value-flow pass recognizes an indirect call when its propagated operand is a concrete decoded instruction address. The pipeline uses a separately bounded discovery pass to add such targets as function candidates, rebuild CFG leaders and function reports, and records its row/function usage and discovered addresses in `summary.json` and `program.json`. It deliberately excludes `.byte` placeholders. Linear-sweep false instruction boundaries remain a source of uncertainty.

The scalability phase added cooperative cancellation and progress reporting. Pipeline callbacks receive stage, completed/total, and cancellation state at function boundaries. A cancellation request stops the current bounded loop and all later expensive function-analysis stages, preserves completed work, emits explicitly partial summaries and warnings, and still writes the normal report set. The CLI exposes opt-in `--progress` and converts Ctrl+C into a cooperative request; cancellation returns conventional status 130. A mocked-PE regression confirms cancellation after the first indexed function yields one function plus partial status metadata. PE parsing, disassembly, and other monolithic stages still cannot be interrupted internally, and incremental/persistent analysis, caching, and parallelism remain future work.

Opaque IR operations now retain a conservative destination definition when their first operand is a recognized scalar or vector register or memory expression, and carry explicit `unknown_effects`, `may_write_memory`, and `may_write_flags` metadata. XMM/YMM/ZMM registers are normalized as separate 128/256/512-bit families, so unsupported vector instructions remain visible and can version their destination in SSA. A regression covers an opaque `paddd`. Separately, value-flow analysis now conservatively invalidates the apparent destination and flags for unmodeled instructions, clears potentially written memory/stack facts, and clears tracked state for unknown no-operand instructions. `push`/`pop`/`leave` discard stack facts and RSP because stack semantics are not modeled there. Focused regressions confirm that `movzx` and `xsave` cannot leave stale values available to later loads. The IR metadata and data-flow fallback currently use separate classification paths; neither implements SIMD/FPU semantics, and conservative invalidation may lose useful facts.

The bounded scalar value-flow pass now folds `movzx`, `movsx`, and `movsxd` when source values are known, applying sign extension from the source operand width and truncating to the destination width. Unknown source values remain unknown. Tests cover 8-to-32 zero/sign extension and 32-to-64 sign extension.

The bounded indirect-call discovery pass now preserves pre-call Windows x64 register arguments and scans them for decoded code addresses. Such values are reported as callback candidates and can seed function discovery/CFG rebuilding, with a distinct reason and `callback_targets` summary field. A mocked-PE integration regression covers a direct call receiving a code pointer in RCX. This is a candidate heuristic: it cannot prove the callee uses the pointer as a callback and does not yet recover x86 stack arguments or dynamic/heap-held targets.

x86 data flow now keeps a bounded, same-basic-block list of pushed values and emits them in call argument order for callback discovery. It clears the list at a call, pop, or `add esp, N` cleanup and retains it across a CFG join only when both incoming states agree. Unit and mocked-pipeline regressions check argument order, cleanup, and callback candidate promotion. This does not model full ESP-relative stack memory or pushes propagated across blocks.

The IR and bounded value-flow interpreter now model a common integer SIMD subset: vector register widths for XMM/YMM/ZMM, `movd`/`movq` and packed vector moves, VEX/non-VEX packed add/subtract by byte/word/dword/qword lanes, packed word/dword/qword logical/arithmetic shifts, packed XOR/OR/AND/AND-NOT, signed/unsigned saturating byte/word add/subtract, rounded unsigned byte/word averages, equality and signed greater-than comparisons, and selected signed/unsigned min/max operations. Concrete vector values fold per lane with the required wrapping or saturation; same-source XOR/subtraction fold to zero even if source values are unknown. Vector writes invalidate tracked aliases of other vector widths to avoid stale upper/lower-width facts. Tests cover typed `vpaddd`/`psrad` IR, XMM dword overflow/extraction, arithmetic shifts, saturating add, equality masks, and YMM XOR/subtraction. This remains a limited integer SIMD subset; floating point, many shuffle/permute/convert/crypto operations, byte/whole-vector shifts, lane extraction, and broad AVX/AVX-512 behavior remain open.

A pair of self-contained minimal PE32 and PE32+ test fixtures contain `mov eax, 42; ret` and run through the actual PE loader, Capstone decoder, CFG construction, and report pipeline. The tests check architecture, entry point, decoded instruction count, function discovery, generated output, and (for x64) recovered constant. This gives reproducible real-format end-to-end coverage without an installed compiler; compiler-produced PE corpora and broader real-world x86/x64 cases remain necessary.

Control-flow structuring now handles acyclic multi-block bodies under a conditional loop header when all paths stay within one natural region and reach only the header or one exit. It verifies that emitted block order preserves fallthrough, rejects outside entries and internal cycles, and converts unconditional or conditional edges to the header/exit into `continue`/`break`. Internal branches remain gotos. A regression covers a multi-block body with conditional continue and break; nested cycles, multiple exits, irreducible regions, and broader AST-based structuring remain open.

Scalar data-flow folding now uses the operation's operand width for constant add/subtract/multiply/bitwise and shift results, masks x86 shift counts to five or six bits, and sign-extends the input for constant arithmetic-right-shift folding. `inc`, `dec`, and `neg` constant results also wrap to operand width. Symbolic results remain bounded expressions. Focused tests cover 32-bit overflow, shift-count masking, and unary overflow.

Arithmetic condition flags now use concrete known-width results for `cmp`/`test`, add/subtract, `adc`/`sbb`, `inc`/`dec`, `neg`, `and`/`or`/`xor`, and common shifts; the tracked bits are CF/PF/AF/ZF/SF/OF. `inc`/`dec` preserve prior CF. Shift count zero preserves the incoming flags; nonzero shifts track result ZF/SF/PF, CF when the last shifted bit is defined, and OF only for count one. Undefined/out-of-range CF/OF and AF are unknown. Unsupported carry/condition writers and disagreeing joins invalidate flag certainty. Known Jcc predicates for equality, unsigned/signed comparisons, overflow, sign, and parity fold to true/false. Tests cover carry/borrow, unknown carry-in, signed overflow, parity, shift boundaries, `inc` preservation, unsupported writers, and flag joins. Multiply/divide and other instruction-specific flag cases remain conservative.

Implicit accumulator arithmetic now handles one-operand unsigned/signed `mul`/`imul` and `div`/`idiv` when source values are known. It tracks the correct low and high result registers (including byte operations through AX), preserves unrelated bits when their values are known, reports implicit high-register writes, and makes results unknown for divide-by-zero or quotient overflow. Multiply CF/OF reflect whether the high half is a sign/zero extension as appropriate; the other multiply/divide flags remain unknown. Tests cover signedness, high/low halves, byte forms, quotient overflow, and a conditional overflow branch. This does not model symbolic products/divisions or every partial-register/undefined-flag nuance.

Atomic read-modify-write IR now distinguishes memory `xchg`, `xadd`, and `cmpxchg` and exposes their source, destination, accumulator, and flag effects rather than treating `xadd` as plain addition. Register-only `xchg` swaps known values in data flow. For memory forms, `xchg` clears potentially aliased memory/stack facts; `xadd` and `cmpxchg` clear memory facts and widen touched registers, avoiding stale-value reuse until a memory-SSA model exists. These operations are visible but their atomic linearization/order, fence behavior, and detailed flag/result propagation are not modeled.

Register-form `bt`/`bts`/`btr`/`btc` now compute CF from the selected bit when both operands are known. The modifying forms also update the destination at operand width; known CF can fold `jc`/`jnc`. Other arithmetic flags are marked unknown as required. Memory bit tests remain conservative because a large or signed bit index can change the addressed word, so the affected memory facts are discarded rather than guessed. Tests cover bit selection, set/reset results, carry branches, and this uncertainty boundary.

Known scalar `not` now complements only the destination-width bits without disturbing flags. `bswap` reverses the bytes of known 32/64-bit register values and likewise preserves flags. `rol`/`ror` and carry-through `rcl`/`rcr` now model known counts using the architectural count mask and effective rotation width; CF is computed, OF is computed for count one, OF becomes unknown for other nonzero counts, and the remaining flags are preserved. A zero effective count preserves all flags. IR exposes rotate reads/writes, including FLAGS as an input to `rcl`/`rcr`. Unknown operands remain unknown, and this does not cover vector rotates or every memory/address-size corner case.

String operations (`movs`, `stos`, `lods`, `cmps`, `scas`, `ins`, and `outs` byte/word/dword/qword forms) now have explicit implicit-operand IR, including RSI/RDI, DF, memory, accumulator, RCX repetition and conditional FLAGS dependencies. For known concrete indices, element width, repeat count and DF, completed operations update RSI/RDI by the total byte distance. A known zero repeat count has no modeled side effects. Compare/scan flags are widened to unknown. Exact element values, address-size/segment overrides, restart/fault behavior and string-memory SSA remain unsupported. Prefixes are also reported separately from the base mnemonic so unsupported or prefixed instructions remain visible.

Register-only `xadd` now computes the width-limited sum, transfers the old destination into the source register, and tracks ADD flags when both inputs are known. Register-only `cmpxchg` compares the implicit accumulator against the destination, writes the source on equality or the old destination to the accumulator on failure, and tracks CMP flags. Unknown inputs widen the affected outputs. Memory forms remain conservative because this analysis has no atomic memory SSA or concurrency model; the compare-exchange source register is preserved because it is read-only.
